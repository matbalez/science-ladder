# Linux proof assets

`python3 tools/proof/build.py NEW_DIRECTORY` builds pinned Lean elaboration/export and proof-checking images. It is an **operator build**, not something challenge participants install. It needs Python 3.12+, zstd, Git and Docker, several GB of storage, and access to the pinned public native and Python base images. The filesystem builder is built from the pinned base and Debian snapshot in the repository; an existing reviewed builder may be supplied with `SL_PROOF_TOOLS_IMAGE`. The script records exact resulting image digests; it does not assert bit-identical compiler output across rebuilds.

The candidate asset contains Lean 4.33.1 and lean4export. The checker asset contains the first-party `sl-lean-check` adapter and DRAT-trim. Full Lean releases include additional tools; this image intentionally contains only elaboration, imported libraries and export. Separately provisioned assets can supply reviewed project dependencies such as Mathlib. C/C++ and Rust use the native profile's compiler domain.

`SLCheck.lean` parses a validated serialized environment from a file stream, compares the frozen statement and kernel primitives using Comparator, enforces the frozen axiom list, then replays declarations through Lean's kernel. The kernel retains the parsed declaration graph in memory; streaming input is not a claim of constant-memory proof checking. Candidate-generated `.olean` files are used only by the isolated elaboration/export process. They are never imported by the authoritative checker. This is official Lean kernel replay, not a second independent kernel implementation.

The bundled reference theorem contains `sorry` to supply its statement. The **solution** must satisfy its separate axiom policy; the fixture has an empty allowlist. Changed statements, `sorryAx`, a custom axiom and malformed serialized syntax must fail. DRAT fixtures include an unsatisfiable formula, a valid certificate, a different satisfiable formula, and an invalid certificate.

Before enrollment, bind image sizes/digests and domains to an exact runtime inventory and primary-source advisory snapshot. Run both `runnerd native-hardware-probe` and `runnerd proof-hardware-probe` on the exact guest/profile, then verify their signed receipts. The latter exercises actual Lean export/replay, DRAT rejection, candidate/checker asset isolation and sealed product limits. Passing this first-party corpus is not an external security audit or challenge scientific approval.

First-party adapter, fixture and build code: MIT. Lean, Comparator and lean4export: Apache-2.0. DRAT-trim: MIT. The build copies upstream notices, including Lean's bundled library notices, into both assets. Exact upstream commits and the official Lean archive digest are in `build.py`.

Proof contracts using this adapter require `private-process-view`: a read-only proc view bound to the candidate’s own PID namespace, with kernel-wide entries hidden. Frozen Lean build commands set `LEAN_SYSROOT=/assets/lean/lean`, `LEAN_PATH=/work:/assets/lean/lean/lib/lean`, `LD_LIBRARY_PATH=/assets/lean/lean/lib/lean`, and prepend `/assets/lean/lean/bin` to `PATH`. The hardware probe exercises these paths inside the actual isolated filesystem.
